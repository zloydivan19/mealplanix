# US-025 — Составная генерация приёмов пищи с реалистичными порциями

**Эпик:** Меню  
**Приоритет:** 🔴 критично  
**Статус:** 📋 не начато  
**Дата:** 2026-04-08

---

## Описание

Как пользователь, я хочу чтобы автоматически сгенерированное меню состояло из
реалистичных порций нескольких блюд в каждом приёме,
чтобы итоговые калории совпадали с моей суточной нормой,
а порции выглядели так, как я реально ем.

---

## Проблема (было)

Каждый слот = одно блюдо с фиксированными ккал (не масштабируемыми).
При норме 2740 ккал генератор ставит пасту на 220 ккал — потому что она "ближайшая",
но не умеет добрать оставшиеся 876 ккал до цели обеда.
Масштабирование порции до 500г — нереалистично.

---

## Решение — составной приём

Каждый приём пищи собирается из **нескольких компонентов** разных ролей.
Каждый компонент масштабируется до целевых ккал, но **в пределах реалистичного диапазона порции**.

---

## Новая классификация блюд

| Категория | Роль в приёме | Типичная порция | Примеры |
|-----------|--------------|-----------------|---------|
| `breakfast` | Основа завтрака | 150–300г | Сырники, каша, яичница, оладьи |
| `main` | Основное в обеде/ужине | 150–300г | Курица, говядина, рыба, паста с белком |
| `side` | Гарнир | 100–250г | Гречка, рис, картошка, макароны |
| `salad` | Салат/овощи | 80–200г | Овощной салат, греческий, цезарь |
| `snack` | Перекус | 50–200г | Орехи, йогурт, фрукты |

> ⚠️ Старые категории `bf / ln / dn / sn` — роль слота (когда едим).
> Новые категории — **роль блюда** (что это такое).
> Это разные понятия, не путать.

## Структура блюда (новый SeedDish)

```typescript
export interface SeedDish {
  id:               number;
  name:             string;
  category:         'breakfast' | 'main' | 'side' | 'salad' | 'snack';
  kcal_per_100g:    number;
  protein_per_100g: number;
  fat_per_100g:     number;
  carbs_per_100g:   number;
  portion_min_g:    number;  // минимальная реалистичная порция
  portion_max_g:    number;  // максимальная реалистичная порция
  portion_default_g: number; // типичная порция (для ручного добавления)
  cost_per_100g:    number;  // стоимость на 100г
  photo?:           string;
}
```

## Состав каждого приёма при генерации

### Завтрак (bf) — цель: `kcal_target × bf%`
```
Компонент 1: breakfast  (70% ккал слота)
Компонент 2: breakfast  (30% ккал слота) — опционально, если остаток > 100 ккал
```

### Обед (ln) — цель: `kcal_target × ln%`
```
Компонент 1: main       (45% ккал слота)
Компонент 2: side       (35% ккал слота)
Компонент 3: salad      (20% ккал слота)
```

### Ужин (dn) — цель: `kcal_target × dn%`
```
Компонент 1: main       (55% ккал слота)
Компонент 2: salad      (45% ккал слота)
```
*(ужин легче обеда — без гарнира)*

### Перекус (sn) — цель: `kcal_target × 10%`
```
Компонент 1: snack  (100% ккал слота)
Компонент 2: snack  — добавляется если после компонента 1
                       фактический недобор > 40% от цели слота
```

## Алгоритм масштабирования порции

Для каждого компонента:

```
target_kcal = slot_kcal × component_ratio

grams = round(target_kcal / dish.kcal_per_100g × 100)
grams = clamp(grams, dish.portion_min_g, dish.portion_max_g)

actual_kcal    = round(grams / 100 × dish.kcal_per_100g)
actual_protein = round(grams / 100 × dish.protein_per_100g)
actual_fat     = round(grams / 100 × dish.fat_per_100g)
actual_carbs   = round(grams / 100 × dish.carbs_per_100g)
actual_cost    = round(grams / 100 × dish.cost_per_100g)
```

**Важно:** `clamp` означает что если нужно 500г пасты — берём максимум 300г.
Недобор ккал допустим, перебор нереалистичной порцией — нет.

### Подсказка о недоборе

Если итоговые ккал дня < `kcal_target × 90%` — в заголовке карточки дня
показываем подсказку:

```
Понедельник, 6 апр   855 ккал   ⚠ до нормы не хватает ~480 ккал
```

- Порог срабатывания: недобор > 10% от суточной нормы
- Цвет текста: `var(--color-warning)` (#F59E0B)
- Показывается только если у персоны включён `match_kcal = true`

## Пример: обед при норме 2740 ккал, ln=40%

```
Цель обеда: 2740 × 40% = 1096 ккал

main  (45%): 493 ккал → Курица с гречкой, 220 ккал/100г
  grams = round(493 / 220 × 100) = 224г → clamp(150, 300) = 224г ✓
  actual = 493 ккал

side  (35%): 384 ккал → Гречка, 150 ккал/100г
  grams = round(384 / 150 × 100) = 256г → clamp(100, 250) = 250г
  actual = 375 ккал

salad (20%): 219 ккал → Овощной салат, 40 ккал/100г
  grams = round(219 / 40 × 100) = 548г → clamp(80, 200) = 200г
  actual = 80 ккал

Итого: 948 ккал (vs цели 1096) — недобор ~13%, что приемлемо
Порции: 224г курицы + 250г гречки + 200г салата ✓ реалистично
```

## Carry dinner → lunch

Переносится только компонент `main` с ужина предыдущего дня.
`side` и `salad` генерируются заново.

**Логика:** на ужин приготовили котлеты (main) и поели с салатом.
На следующий обед котлеты остались — берём их как main.
Но гарнир и салат делаем свежие.

```
Пн ужин:  main=Котлеты  +  salad=Греческий
Вт обед:  main=Котлеты (←ужин Пн)  +  side=Гречка (новый)  +  salad=Капустный (новый)
```

Нужно переписать все блюда в новом формате. Примерный набор:

### breakfast (7 шт.)
Сырники, овсянка, яичница, оладьи, бутерброд, блин из яйца, оладьи из батата

### main (8–10 шт.)
Куриное филе, говядина тушёная, индейка, лосось запечённый, тунец, свинина, фарш (котлеты), паста с соусом болоньезе

### salad (5–7 шт.)
Овощной (огурец+помидор), греческий, цезарь без курицы, капустный, морковный, свекольный

### snack (7 шт.)
Яблоко+орехи, творог с мёдом, банан+арахисовая паста, кефир, хлебцы с авокадо, йогурт с ягодами, сыр+виноград
