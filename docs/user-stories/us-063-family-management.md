# US-063 — Управление семьёй

**Дата:** 2026-04-14
**Статус:** утверждено
**Эпик:** Эпик 6 — Семья и персоны
**Задачи:** V5-063, V5-064, V5-065

---

## Цель

Владелец домохозяйства может пригласить членов семьи по коду или ссылке. Приглашённый отправляет заявку, владелец одобряет или отклоняет. После принятия оба видят общие персоны, меню и корзину.

---

## User Stories

### US-063-A — Блок семьи в настройках
**Как** владелец домохозяйства  
**Я хочу** видеть список участников своей семьи и управлять ими  
**Чтобы** знать кто имеет доступ к общему плану

**Acceptance criteria:**
- На странице `/settings` новая секция «Моя семья»
- Показывает: текущий пользователь (с меткой «Владелец») + список участников с email / display_name
- Владелец может удалить участника — при удалении `household_members.household_id` участника возвращается к его `own_household_id`
- Участник видит: «Вы участник семьи [name]» + кнопка «Выйти из семьи» (аналогичный эффект)
- Если пользователь — единственный владелец, кнопка «Выйти» отсутствует

### US-063-B — Приглашение по коду и ссылке
**Как** владелец домохозяйства  
**Я хочу** поделиться инвайт-кодом или ссылкой  
**Чтобы** быстро добавить члена семьи без передачи логина/пароля

**Acceptance criteria:**
- В секции «Моя семья» отображается `invite_code` из таблицы `households`
- Кнопка «Скопировать код» — копирует код в буфер
- Кнопка «Поделиться ссылкой» — копирует ссылку `{origin}/join?code={invite_code}`
- Кнопка «Обновить код» — генерирует новый `invite_code` (защита от утечки старого)

### US-063-C — Страница /join: отправка заявки
**Как** пользователь с инвайт-ссылкой  
**Я хочу** вступить в домохозяйство по коду  
**Чтобы** получить доступ к общему планированию семьи

**Acceptance criteria:**
- Маршрут `/join?code=XXXXXX` доступен для авторизованных пользователей
- Неавторизованный — редирект на `/auth?redirect=/join?code=XXXXXX`, после входа возвращается на /join
- Страница показывает: название домохозяйства, количество участников, кнопку «Отправить заявку»
- Если код не найден — сообщение «Код недействителен или истёк»
- Если пользователь уже в этом домохозяйстве — сообщение «Вы уже участник этой семьи»
- После отправки: статус заявки `pending`, toast «Заявка отправлена. Ожидайте одобрения.»
- Повторная заявка при уже существующей `pending` — показывает «Заявка уже отправлена»

### US-063-D — Одобрение / отклонение заявок
**Как** владелец домохозяйства  
**Я хочу** видеть входящие заявки и принимать решение  
**Чтобы** контролировать кто получает доступ к семейному плану

**Acceptance criteria:**
- В секции «Моя семья» счётчик-бейдж если есть `pending` заявки
- Список заявок: email / display_name заявителя, дата заявки, кнопки «Принять» / «Отклонить»
- **Принять:** `household_join_requests.status = 'approved'` + `household_members.household_id` заявителя = `household_id` владельца; `own_household_id` заявителя — не трогать
- **Отклонить:** `household_join_requests.status = 'rejected'`; пользователь остаётся в своём домохозяйстве
- После одобрения заявитель при следующей загрузке видит общие персоны и меню

## Схема БД

Используются существующие таблицы без изменений схемы:
- `households.invite_code` — уже есть
- `household_members.household_id` / `own_household_id` — уже есть
- `household_join_requests` (`household_id`, `requester_user_id`, `status`) — уже есть

⚠️ Проверить RLS-политики на `household_join_requests` и `household_members` перед реализацией — при смене `household_id` пользователь должен потерять доступ к данным своего старого домохозяйства, но не к `own_household_id`-данным.
