# Печать меню на неделю (A4)

**Дата:** 2026-07-27
**Статус:** ✅ утверждено (дизайн)

## Задача

Пользователь хочет распечатать меню на неделю на листе A4, чтобы повесить на холодильник. Нужен опрятный, читаемый макет для печати — не текущая интерактивная таблица WeekGrid (она не рассчитана на печать: узкие колонки, кнопки, drag-хендлы).

## Область

- Печатается меню **только активной персоны** (той, чья вкладка открыта в планировщике сейчас).
- Реализация полностью клиентская: новых полей в БД, новых API-запросов и новых SvelteKit-роутов не требуется. Все данные уже загружены в `+page.svelte` (`data.menuPlans` содержит все недели персон домохозяйства; `localPlans` — уже сгруппированная Map по `persona_id__week_label__day_index__meal_key`).

## Точка входа

- Кнопка **«🖨 Печать»** в шапке WeekGrid — рядом с существующим переключателем Неделя/День (US-015).
- По клику включается локальный флаг `printMode = $state(false)` в `src/routes/+page.svelte` — так же, как уже работает переключение Неделя/День (без роутинга, без перезагрузки данных).
- Внутри режима печати — кнопка «← Назад к меню» (возврат `printMode = false`) и кнопка «🖨 Распечатать» (`window.print()`).

## Компонент

Новый файл `src/lib/components/PrintMenu.svelte`.

**Пропсы:**
- `persona: Persona`
- `weekLabel: string` (человекочитаемый диапазон дат, из `getWeekLabel()`)
- `days: PrintDay[]` — подготовленные данные по 7 дням (см. ниже)

```ts
interface PrintMealEntry {
  mealKey: MealKey;
  label: string;        // MEAL_LABELS[mealKey]
  dishNames: string[];  // может быть несколько блюд в одном приёме
}

interface PrintDay {
  dayIdx: number;       // 0..6
  label: string;        // "Понедельник"
  meals: PrintMealEntry[]; // только непустые приёмы пищи
  totals: { kcal: number; protein: number; fat: number; carbs: number } | null; // null если день пуст
}
```

Данные для `days` собираются на странице `+page.svelte` из уже существующего `localPlans` фильтрацией по `activePersona.id` + текущему `weekId`, суммированием КБЖУ по всем строкам дня. Никакой новой загрузки с сервера.

## Разметка печатного листа

Сверху вниз, по центру страницы:

1. **Брендовая шапка** — иконка (36px, как в сайдбаре) + wordmark «MealPlani**X**» тем же стилем, что в `Sidebar.svelte` (`--color-text-primary` + `--color-green-primary` для «X», font-weight 800). Без бейджа "beta".
2. **Заголовок листа** — «Меню на неделю» (H3-подобный стиль).
3. **Подзаголовок** — период недели (`weekLabel`) + имя персоны, например «14 июл – 20 июл · Иван».
4. **Сетка дней в 2 колонки:**
   - Левая колонка: Понедельник, Вторник, Среда.
   - Правая колонка: Четверг, Пятница, Суббота.
   - Тонкий вертикальный разделитель между колонками.
5. **Воскресенье** — отдельным блоком по центру под колонками, на всю ширину листа.
6. Внутри каждого дня: название дня жирным, затем строки «Приём: блюдо, блюдо» (только непустые приёмы; несколько блюд — через запятую). Если день полностью пуст — одна строка серым «День не запланирован» вместо списка приёмов.
7. Под списком приёмов каждого дня — **итог за день** одной строкой мелким серым шрифтом: «1210 ккал · Б75 Ж30 У140». Если день пуст — итог не выводится.
8. Футер листа (мелкий серый текст, по центру): «Mealplanix · сгенерировано {дата}».

Без КБЖУ по каждому блюду отдельно — только итог за день (решение принято в брейнстроминге: показывать КБЖУ по блюду сейчас преждевременно, расчёты "не доведены до идеала").

## CSS для печати

- `@page { size: A4; margin: 12mm; }`
- `@media print`:
  - Скрыть сайдбар, шапку WeekGrid, кнопки «Назад»/«Распечатать» и всё, что не входит в `.print-sheet`.
  - Принудительно светлая тема — переопределить CSS-переменные темы (`--color-bg-page`, `--color-bg-card`, `--color-text-primary`, `--color-text-muted`, `--color-border`) на светлые значения из `BRAND.md` независимо от `data-theme="dark"` на `<html>`.
  - Шрифты и отступы подобраны так, чтобы все 7 дней помещались на один лист A4 (см. утверждённый мокап: заголовки дней ~12px, текст приёмов ~10.5px, итоги ~9px).
- `@media screen` — тот же `.print-sheet` показывается как превью (белый лист по центру экрана с тенью), чтобы пользователь видел результат до печати.

## Обработка ошибок / edge-кейсы

- День без единого блюда → «День не запланирован» вместо пустых строк приёмов.
- Несколько блюд в одном приёме пищи (поддерживается V5-024) → перечисляются через запятую в одной строке.
- Длинные названия блюд/персон — переносятся по словам, не обрезаются (тестируется вручную).
- Печать в тёмной теме приложения не должна протекать в печатный лист (принудительный светлый CSS).

## Тестирование

Ручное — автоматических тестов для этой фичи не предполагается (чисто визуальная фича):
- Переключение в режим печати и обратно на пустой неделе, на неделе с частично заполненными днями, на полностью заполненной неделе.
- Slot с несколькими блюдами — корректное перечисление через запятую.
- Длинные имена персон/блюд — не ломают вёрстку.
- Просмотр через Ctrl+P / предпросмотр браузера — лист умещается на одну страницу A4.
- Тёмная тема приложения включена → печатный лист остаётся светлым.

## Вне области (не делаем сейчас)

- Печать меню нескольких персон домохозяйства за один раз.
- Генерация PDF-файла (используем нативный `window.print()`).
- КБЖУ по каждому блюду на распечатке.
