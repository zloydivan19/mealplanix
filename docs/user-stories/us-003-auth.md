# US-003 — Авторизация и защита маршрутов

**Эпик:** Инфраструктура  
**Приоритет:** 🔴 критично  
**Статус:** ✔️ готово  
**Дата:** 2026-04-07

## Описание
Как пользователь, я хочу входить в сервис по почте и паролю,
чтобы мои данные были приватными и доступными только мне.

## Сценарии

### SC-1: Вход
1. Открываю `/auth`, вижу форму с табами "Войти" / "Регистрация"
2. Ввожу почту и пароль, нажимаю "Войти"
3. Меня перенаправляет на главную страницу `/`

### SC-2: Регистрация
1. Переключаюсь на таб "Регистрация"
2. Ввожу почту и пароль (мин. 6 символов), нажимаю "Создать аккаунт"
3. Supabase создаёт пользователя, trigger создаёт профиль + домохозяйство
4. Меня перенаправляет на `/onboarding` (т.к. персоны ещё нет)

### SC-3: Выход
1. Нажимаю "Выйти" в хедере
2. Меня перенаправляет на `/auth`

### SC-4: Защита маршрутов
- Не авторизован → автоматический редирект на `/auth`
- Авторизован, зашёл на `/auth` → редирект на `/`
- Авторизован, нет персоны, не на `/onboarding` → редирект на `/onboarding`

## Архитектурные решения
- `window.location.replace()` вместо `invalidate + goto`: браузерная навигация надёжнее ждёт установки сессионных cookie
- `safeGetSession()` использует `getUser()` (обращается к серверу Supabase), а не только `getSession()` (читает cookie без проверки) — требование безопасности
