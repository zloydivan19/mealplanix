# US-050 — Холодильник

**Дата:** 2026-04-11  
**Статус:** утверждено  
**Эпик:** Эпик 5 — Холодильник

---

## Цель

Пользователь ведёт учёт продуктов в холодильнике. При формировании корзины система автоматически вычитает то, что уже есть, и показывает только то, что реально нужно купить.

---

## User Stories

### US-050-A — Страница /fridge: просмотр и добавление
**Как** пользователь  
**Я хочу** видеть список продуктов в холодильнике с количеством  
**Чтобы** понимать что уже есть дома

**Acceptance criteria:**
- Страница `/fridge` доступна из сайдбара
- Список продуктов: название, qty, unit
- Просроченные продукты выделены красным
- Пустой холодильник — заглушка с подсказкой

### US-050-B — CRUD продуктов
**Как** пользователь  
**Я хочу** добавлять, редактировать и удалять продукты  
**Чтобы** поддерживать актуальный список

**Acceptance criteria:**
- Кнопка «+ Добавить» открывает модалку
- Поля: название (text), количество (number), единица (г/мл/шт/упак), срок годности (date, опционально)
- Инлайн-редактирование qty прямо в строке
- Удаление с подтверждением
- Синхронизация с Supabase

### US-050-C — Вычитание из корзины
**Как** пользователь  
**Я хочу** чтобы корзина показывала «нужно купить» = «нужно за неделю» − «есть в холодильнике»  
**Чтобы** не покупать лишнее

**Acceptance criteria:**
- В корзине рядом с qty появляется `(в холод. −N)` если продукт есть в холодильнике
- Колонка «Нужно купить» = max(0, totalQty − fridgeQty)
- Совпадение по точному названию (case-insensitive)

## Схема БД

```sql
CREATE TABLE public.household_fridge (
  id          bigserial PRIMARY KEY,
  household_id text NOT NULL,
  product_name text NOT NULL,
  qty         numeric NOT NULL DEFAULT 0,
  unit        text NOT NULL DEFAULT 'г',
  expires_at  date,
  created_at  timestamptz DEFAULT now(),
  updated_at  timestamptz DEFAULT now()
);
```
