# ТЗ: генерация расширенной базы блюд для food_catalog

## Контекст

Ты генерируешь SQL INSERT-скрипт для таблицы `food_catalog` — базы блюд приложения для планирования питания русскоязычных семей (Россия / СНГ).

Блюда используются для:
- Автогенерации недельного меню по норме КБЖУ
- Ручного добавления в слоты завтрак / обед / ужин / перекус
- Формирования списка покупок через ингредиенты

---

## Схема таблицы

```sql
CREATE TABLE public.food_catalog (
  id                bigserial PRIMARY KEY,
  name              text NOT NULL,
  kcal_per_100g     numeric NOT NULL,  -- ККАЛ НА 100 ГРАММОВ блюда
  protein_per_100g  numeric NOT NULL,  -- БЕЛКИ НА 100 ГРАММОВ
  fat_per_100g      numeric NOT NULL,  -- ЖИРЫ НА 100 ГРАММОВ
  carbs_per_100g    numeric NOT NULL,  -- УГЛЕВОДЫ НА 100 ГРАММОВ
  category          text NOT NULL,     -- meal slot (см. ниже)
  portion_default_g integer NOT NULL,  -- стандартная порция в граммах
  cost_per_100g     numeric NOT NULL,  -- стоимость 100г блюда в рублях (Москва 2025)
  standalone        boolean DEFAULT false, -- блюдо подаётся само без гарнира
  ingredients       jsonb NOT NULL     -- ингредиенты (см. ниже)
);
```

---

## Категории блюд (поле `category`)

| Значение | Описание | Когда используется |
|----------|----------|-------------------|
| `breakfast` | Завтрак | Утром: каши, яичные блюда, творог, блины |
| `main` | Основное блюдо | Обед/ужин: мясо, рыба, птица |
| `side` | Гарнир | К основному: крупы, овощи, картофель |
| `salad` | Салат/овощи | Лёгкий компонент обеда/ужина |
| `snack` | Перекус | Между приёмами: фрукты, йогурт, орехи |

---

## Структура поля `ingredients` (JSONB)

Массив ингредиентов. **`qty` — количество на ОДНУ порцию** (равную `portion_default_g`).

```json
[
  {"name": "куриное филе", "category": "meat",      "qty": 220, "unit": "г"},
  {"name": "чеснок",       "category": "vegetable", "qty": 10,  "unit": "г"},
  {"name": "масло оливк.", "category": "condiment", "qty": 15,  "unit": "мл"},
  {"name": "соль",         "category": "condiment", "qty": 1,   "unit": "щепотка"}
]
```

### Категории ингредиентов (`ingredients[].category`)

| Значение | Что входит |
|----------|-----------|
| `meat` | Мясо, птица, рыба, морепродукты, колбасные изделия, пельмени |
| `dairy` | Молоко, сыр, творог, яйца, кефир, йогурт, сметана, масло сливочное |
| `grain` | Крупы, макароны, хлеб, мука, рис, гречка |
| `vegetable` | Овощи, зелень, грибы, чеснок, лук |
| `fruit` | Фрукты, ягоды, сухофрукты |
| `condiment` | Масло растительное/оливковое, специи, соусы, томатная паста, уксус |
| `other` | Всё что не входит в выше перечисленное |

### Допустимые значения `unit`

`г` | `мл` | `шт` | `щепотка`

## Требования к КБЖУ

⚠️ **КРИТИЧЕСКИ ВАЖНО: все значения КБЖУ — на 100 граммов блюда, не на порцию!**

Проверка корректности: `protein * 4 + fat * 9 + carbs * 4 ≈ kcal_per_100g` (допуск ±8%).

Реалистичные диапазоны `kcal_per_100g` по категориям:
- `breakfast`: 100–320 ккал/100г
- `main`: 120–350 ккал/100г  
- `side`: 80–200 ккал/100г
- `salad`: 20–150 ккал/100г (овощные салаты очень низкокалорийные!)
- `snack`: 50–400 ккал/100г

## Требования к порциям (`portion_default_g`)

| Категория | Типичный диапазон |
|-----------|-----------------|
| `breakfast` | 150–300 г |
| `main` | 180–280 г |
| `side` | 150–250 г |
| `salad` | 100–200 г |
| `snack` | 100–250 г |

---

## Поле `standalone`

`standalone = true` — блюдо самодостаточно, гарнир не нужен.

**Правило:** `standalone = true` только если в блюде одновременно присутствует и белок (мясо/рыба/бобовые) и углевод (крупа/картофель/макароны/хлеб). Без обоих компонентов — `false`.

| Блюдо | standalone | Почему |
|-------|-----------|--------|
| Свинина с картошкой в духовке | `true` | есть мясо + картофель |
| Макароны по-флотски | `true` | есть макароны + фарш |
| Пельмени | `true` | тесто + мясо внутри |
| Куриное филе запечённое | `false` | только белок, нет углевода |
| Рыба жареная | `false` | только белок |
| Котлеты домашние | `false` | только белок (хлеб — панировка, не гарнир) |

## Требования к ассортименту

⚠️ **Генерируй порциями по 30–40 блюд за запрос**, не всё сразу. После каждой порции жди подтверждения и проверки перед следующей. Так качество КБЖУ и ингредиентов будет стабильным до конца.

Цель — **120 новых блюд** (сверх уже существующих 78) со следующим распределением:

| Категория | Кол-во | Примеры типов |
|-----------|--------|---------------|
| `breakfast` | 30 | каши, яичные, творожные, блины, оладьи, тосты, смузи-боулы |
| `main` | 45 | говядина, свинина, курица, индейка, рыба, морепродукты, вегетарианские |
| `side` | 20 | крупы, макароны, овощи тушёные, картофель |
| `salad` | 15 | овощные, с белком, греческий, цезарь, азиатские |
| `snack` | 10 | фрукты, молочные, ореховые, батончики |

Разнообразие обязательно:
- Не менее 8 вегетарианских/рыбных вариантов в `main`
- Не менее 5 бюджетных блюд (cost_per_100g ≤ 25 руб) в каждой категории
- Не менее 3 блюд с высоким белком (protein ≥ 20г/100г) в `breakfast`

## Формат SQL

```sql
INSERT INTO public.food_catalog (name, kcal_per_100g, protein_per_100g, fat_per_100g, carbs_per_100g, category, portion_default_g, cost_per_100g, standalone, ingredients) VALUES

('Название блюда', 145.0, 10.5, 10.2, 3.5, 'breakfast', 180, 22.0, false,
 '[{"name":"яйца","category":"dairy","qty":2,"unit":"шт"},{"name":"помидоры","category":"vegetable","qty":100,"unit":"г"}]'),

-- ... остальные блюда
;
```

Правила форматирования:
- Одно блюдо = одна строка VALUES
- КБЖУ с одним десятичным знаком: `145.0`, не `145`
- `qty` для счётных продуктов: `0.5` (половина лимона), `1`, `2` — без единицы "шт" при дробных
- Имена блюд на русском языке
- Ингредиенты: 4–10 позиций на блюдо, без воды (вода не покупается)

## Пример готового блюда (для сверки)

```sql
('Омлет с помидорами', 145.0, 10.5, 10.2, 3.5, 'breakfast', 180, 22.0, false,
 '[{"name":"яйца","category":"dairy","qty":2,"unit":"шт"},{"name":"молоко","category":"dairy","qty":50,"unit":"мл"},{"name":"помидоры","category":"vegetable","qty":100,"unit":"г"},{"name":"масло сливочное","category":"condiment","qty":10,"unit":"г"},{"name":"соль","category":"condiment","qty":1,"unit":"щепотка"}]'),
```

Проверка КБЖУ: `10.5 × 4 + 10.2 × 9 + 3.5 × 4 = 42 + 91.8 + 14 = 147.8` ≈ 145 ✓ (в пределах 8%)

---

## Самопроверка перед выводом

Перед тем как выдать SQL, для каждого блюда мысленно проверь:

1. **КБЖУ на 100г?** Возьми `portion_default_g`, умножь КБЖУ на `portion_default_g / 100` — это должны быть реалистичные цифры для одной порции.
2. **Формула ккал:** `protein × 4 + fat × 9 + carbs × 4` должно быть в пределах ±8% от `kcal_per_100g`.
3. **JSON валиден?** Нет лишних запятых, все строки в кавычках, массив закрыт `]`.
4. **`qty` соответствует `portion_default_g`?** Если порция 200г, суммарный вес ингредиентов должен быть ~200г (с поправкой на усадку при готовке ±30%).

## Частые ошибки — НЕ ДЕЛАЙ ТАК

❌ КБЖУ на порцию вместо на 100г (самая частая ошибка!)
```sql
-- НЕПРАВИЛЬНО: омлет 180г, ккал на порцию = 261 — это не на 100г!
('Омлет', 261.0, ...)
-- ПРАВИЛЬНО: делим на 1.8 → 145 ккал/100г
('Омлет', 145.0, ...)
```

❌ Яйца в категории `meat` (яйца — `dairy`)

❌ Масло растительное в категории `dairy` (масло растит. — `condiment`)

❌ Слишком большие порции салата (≥ 300г) — реалистично 100–200г

❌ Нереалистичный белок в кашах (`protein > 8` у овсянки — это ошибка)

❌ Один и тот же белковый источник в 10+ блюдах подряд (нужно разнообразие)
